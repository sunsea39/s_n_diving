# N×S_Diving 改修仕様 v2.8

**セキュリティの前提**（v2.2 と同じ）：権限判定は NULL を返さない（`coalesce(…, false)`）、PL/pgSQL は `if auth.uid() is null or not coalesce(public.is_owner(), false) then raise …`、新しい関数は `revoke execute … from public, anon`。

新しい migration：`supabase/migrations/20261001000000_v2_8.sql`（追加で実行、再実行しても安全）。

## 1. 管理画面：資料・お知らせ・事故事例を 1 件ずつ削除できる

- 削除の権限は DB 側ですでに正しく設定済み（資料・事故事例＝メインの管理者、お知らせ＝サブ管理者以上。Claude 確認済み）。**画面にボタンを付けるだけ**でよい
- 置き場所：
  - 各一覧（`/admin/docs`・`/admin/news`・`/admin/accidents`）の各行の右端に **「削除」**（赤系の小さなボタン。並び替えモード中の資料一覧では出さない）
  - 各編集画面の下部、保存ボタンから離した位置に **「この◯◯を削除」**
- 確認：ページ内のダイアログ（`window.confirm` は使わない）「『（タイトル）』を削除します。元に戻せません。」＋「削除する」（赤）／「キャンセル」。資料の場合は、ブックマークしている人がいても削除されること、ダイビング入門の資料は `manual-seed.sql` を実行し直せば戻せることを小さく添える
- 削除後：一覧から消し、「削除しました」のトースト。編集画面から削除したときは一覧へ戻る。トップ・一覧のデータ（AppData）も再読み込み
- 削除された記事を参照している箇所の後始末（画面側）：
  - マイページのブックマーク：資料が見つからないものは「削除された資料」と表示し、削除ボタンで外せる（リンクにしない）
  - ベルのお知らせ一覧：対象が削除されたものは「（削除されました）」と表示しリンクにしない。もしくは、開いたページの 404 表示に「この記事は削除されました」を出す（どちらか簡単な方）
  - 事故事例の「関連資料」：存在しない資料は表示しない（既にそうなっていれば確認のみ）

## 2. ホームの「資料」欄に出す資料を管理画面で選ぶ（最大 4 件）

- DB：`docs` に列 `home_featured boolean not null default false` を追加
  - トリガー（security definer 不要、`before insert or update`）：`home_featured = true` の行が 4 件を超える更新はエラー「ホームに表示できる資料は4件までです。」
- 管理画面の資料一覧：各行に **「ホームに表示」チェックボックス**
  - 4 件チェック済みのときは、ほかのチェックボックスを押せない（理由を小さく表示「ホームに表示できるのは4件までです」）
  - チェックの変更はその場で保存（失敗したら元に戻してエラー表示）
  - 下書きの資料もチェックできるが、ホームには公開中のものだけ出る旨を小さく表示
- ホーム：`home_featured = true` かつ公開中の資料を、資料の並び順（`sort_order`）で最大 4 件表示
  - 1 件もチェックされていないときは、今まで通り「最新更新の 4 件」
- 資料の編集画面にも同じ「ホームに表示」のチェック（4 件の上限の判定は同じ）

## 3. ホーム：NEXT DIVE の「担当」

- 「担当：◯◯」の文字の大きさを **場所と同じ** にする
- 日程・場所と **同じ行の右端** に置く（flex、`justify-content: space-between`）。スマホで入りきらないときは、担当が次の行の右端に回る（左寄せにしない）
- 担当が空のときは何も出さない
